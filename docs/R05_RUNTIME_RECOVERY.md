This is owner-reported manual evidence, independent of the synthetic CI. Keep the commercial ZIP and all original game resources private.

**Scope and precedence:** stabilize audio, targeted scene loading and game-over recovery before starting R06 art improvements. Character/prop/scene visual quality must pass the artistic gates before creating a general cinematic authoring pipeline. The public launcher design needs redesign; retain its working import behavior until a separate visual review.

## Audio diagnosis before any driver change

`LBA.CFG` generated by `scripts/runtime/build-private-jsdos.py` deliberately disables wave, mixer and MIDI. The archived game binaries can boot, but Sound Blaster hardware emulation alone cannot make the original DOS executable produce audio.

In the published original [ADELINE.C](https://github.com/LBALab/lba1-classic-community/blob/main/LIB386/LIB_SYS/ADELINE.C), the engine calls `WaveInitDLL(WaveDriver)`. The DOS [WAVE.C](https://github.com/LBALab/lba1-classic-community/blob/main/LIB386/PLATFORM/DOS/LIB_SAMP/WAVE.C) loads the named driver file and fails initialization if it is absent. The historic docs do not establish that GOG's `Speedrun/Windows/` folder contains this binary. A made-up `WaveDriver: SB16` setting is unsafe.

Check the actual GOG installation **read-only** (no Windows NVMe access):

~~~bash
cd ~/Documents/lba-custom-portfolio
git pull --ff-only
BASE=/mnt/fast-ssd/Games/Heroic/tlba-classic/Speedrun/Windows
python3 scripts/runtime/audit-dos-install.py --base "$BASE"
~~~

The diagnostic prints only resource names, `LBA.CFG` audio settings and installed driver filenames. The private builder supports `--audio off` (the known working baseline), experimental `--audio source-wave` and guarded `--audio sb16`. The source-wave mode requires `LBA.CFG` to name an installed DOS wave DLL, `WaveExec=NoExec`, port 220h, IRQ 7, DMA 1 and a checked sample rate. The `sb16` mode is an independent experiment using the owner-supplied `W_SB16.DLL` at the same 220h/IRQ7/DMA1 settings even if the source configuration disables audio. If the local DOS DLL is missing or has an unexpected size, the SB16 builder fails closed. MIDI and mixer remain disabled; successful packaging does not prove sound.

**Audio validation sequence:** first prove that a real wave DLL is available; then create separate baseline and wave-enabled private ZIPs; test SFX in the same scene and compare startup, responsiveness and browser errors. Music and voices require separate backends, asset sizes and test gates. The presence of `SAMPLES.HQR` alone does not prove that effects are audible.

## Reproducing and isolating the black screen on death

The owner reports a black screen after death. Original code enters `GameOver()` after the last life, draws a `RESS_GAME_OVER` 3D object and eventually returns. The sequence also calls a sample numbered 37. Test reproducibly before trying to fix it.

1. Run the known-good *audio off* ZIP. Take a screenshot immediately before death and one after the screen goes black.
2. Distinguish loss of a single life (clover respawn) from a final game over. Check if the browser canvas remains responsive after at least 15 seconds and try ESC.
3. Repeat with the museum save if it loads, to isolate scene-specific life scripts.
4. Capture the browser console and approximate delay. Compare a clean native DOSBox run using the *same* private game files if available.
5. Only after reproduction, trace `GameOver()` transitions, `RESS_GAME_OVER` extraction, palette restoration, and sample 37.

A safe reload from the public launcher is a recovery workaround, **not** a fix to the game-over bug.

## R05.2 - Owner runtime results and controlled audio comparisons

Owner-observed on 2026-11-13:
- Loading the Museum DOS save (S003) works in real gameplay; not all seven
  locations have yet been validated for walking/collisions.
- A non-final death now returns to the last checkpoint. Terminal Game Over
  remains unverified.
- The original 16-bit SB16 bundle starts and plays, but audio effects remain
  extremely faint and muffled, matching the earlier observed audio defect.
- Browser reports DOSBox illegal-memory reads and writes. These messages
  alone do not localize the fault to the sound hardware; compare with the
  silent reference. Missing source maps and favicon are not audio errors.

Source verification from lba1-classic-community:
- The original WAVE_DLL.MAK builds W_SB16.DLL as SB16 stereo 16-bit and
  W_SB16_8.DLL as SB16 stereo 8-bit. Thus bit-depth is a controlled variable.
- For the SB16-specific driver, WAVE_A.ASM asks for WaveBase and WaveRate,
  not WaveIRQ/WaveDMA. Earlier suspicion about WaveDMA=1 misconfiguring
  the 16-bit driver was not justified. DOSBox emulates low DMA 1 and high
  DMA 5 separately.
- When MixerDriver is disabled, MIXER_I.ASM bypasses mixer calls. When
  M_SB16.DLL is loaded, MIXER_A.ASM writes PCM and master hardware levels.
  SOURCES/PERSO.C reads the WaveVolume and MasterVolume config values.
- Blank WaveIRQ/WaveDMA in the owner GOG config are therefore consistent
  with the driver's SB16-specific configuration requirements.

Controlled audio bundles, all private in output/r05-probes/:

| File | Driver | Mixer | PCM/master | Isolated variable |
| --- | --- | --- | --- | --- |
| r05-sb16.jsdos | W_SB16.DLL | NoMixer | 163 / 128 | Original audio reference |
| r05-sb16-8.jsdos | W_SB16_8.DLL | NoMixer | 163 / 128 | Output 8-bit vs 16-bit |
| r05-sb16-mixer.jsdos | W_SB16.DLL | M_SB16.DLL | 163 / 128 | Mixer enabled only |
| r05-sb16-mixer-loud.jsdos | W_SB16.DLL | M_SB16.DLL | 240 / 240 | Volume relative to mixer bundle |

The silent control bundle is unchanged. These extra profiles only use
owner-provided original DOS DLLs. Successful archive construction does
not imply audio quality; no original game files are committed or hosted.

## R05.3 - Audible owner tests and two new targeted probes

Owner reported after the R05.2 experiment:
- r05-sb16-8.jsdos: audible footsteps and clearer feedback while moving
  the music-volume slider, but the audio is still muffled in Museum and
  music is barely present.
- r05-sb16-mixer.jsdos and r05-sb16-mixer-loud.jsdos: **completely silent**.
  Stop using the mixer variants; higher in-game volume did not help.
- The browser console in the non-mixer version still prints illegal-memory
  access warnings; no trace yet isolates those warnings as audio-related.
- Game save-loading, including Museum, and checkpoint respawn remain usable.

Source-level diagnosis:
- The generated GAME_CONFIG uses MidiDriver: NoMidi. Original
  SOURCES/AMBIANCE.C::PlayMidiFile returns immediately when
  Midi_Driver_Enable is false; MIDI_SB.HQR is present but unused.
- Original SOURCES/PERSO.C selects MIDI_SB.HQR when MidiType: FM.
  The original DOS Miles driver A32SBFM.DLL can synthesize via the
  emulated OPL in a separate, opt-in comparison.
- The original SOURCES/AMBIANCE.C::PlayMusic sends most scene music to
  CD-DA when CDEnable is true; the guarded RELENT.EXE patch forces the
  DOS CD-drive check to succeed. However the locally generated LBA.ISO
  only contains a CD_LBA marker and SAMPLES.HQR, not Red Book audio.
  This is a separate structural reason for the lack of soundtrack.
  Enabling FM can validate the original MIDI pathway but **will not**
  automatically restore the audio tracks missing from this data-only ISO.
- The community build's W_SB16_M.DLL is 16-bit mono. Comparing it to
  the previously tested W_SB16.DLL 16-bit stereo isolates output
  channel layout without a new PCM mixer.

New isolated private tests under output/r05-probes/:

| Profile | Wave driver | MIDI | Mixer | Diagnostic question |
| --- | --- | --- | --- | --- |
| sb16-8 | W_SB16_8.DLL | NoMidi | NoMixer | Known partially audible baseline |
| sb16-mono | W_SB16_M.DLL | NoMidi | NoMixer | 16-bit mono vs 16-bit stereo |
| sb16-8-fm | W_SB16_8.DLL | A32SBFM.DLL (FM/OPL) | NoMixer | Can the old Miles FM pathway initialize/play? |

The FM profile uses the owner's original A32SBFM.DLL + MIDI_SB.HQR,
and sets MidiBase/IRQ/DMA to -1 to preserve Miles driver defaults.
In the original DOS MIDI.C code, -1 means 'do not override driver
hardware defaults'. Both probes must still be validated in the
owner's running browser; synthetic CI is packaging coverage only.

Owner's test order:
1. Keep sb16-8 as unchanged audible reference.
2. Import sb16-mono and repeat exactly the same footstep and menu
   sample comparisons. If mono removes distortion, focus on emulated
   stereo channel handling; if not, isolate old 16-bit DMA next.
3. Import sb16-8-fm and check for MIDI music/tones during title/menu
   transitions and any MIDI-only scripted events, **without** treating
   missing CD soundtrack during ordinary scenes as an FM failure.
   Test starts, responsiveness and browser log for new MIDI errors.
4. If FM fails, return to sb16-8; do not enable original MIDI by
   default. A proper CD music path requires a separate licensed
   owner-local audio-track source and architecture decision.

Do not publish any GOG audio tracks, MIDI assets, proprietary DLLs,
or generated game bundles. No new patches to game executable.


## R05.4 - Miles Sound Blaster FM hardware detection failure

Owner's screenshot of r05-sb16-8-fm.jsdos shows the DOS game exits
during MIDI initialization and returns to the C:\ prompt:

    AIL/32 midi driver for:
    Creative Labs Sound Blaster(TM) FM Sound
    Media Vision Thunderboard(TM) FM Sound
    Error MidiDriver: Sound Hardware not found.

This locates the immediate failure at the original InitMidi() ->
AIL_detect_device() check in LIB386/PLATFORM/DOS/LIB_MIDI/MIDI.C.
The original A32SBFM.DLL loaded and was recognized, but its
hardware probe failed. The exact cause (driver default port,
emulated hardware response, or timing) is not established.
LIB386/LIB_SYS/ADELINE.C calls exit(1) on InitMidi() failure.

The mono browser log shows emulator illegal-memory access warnings,
but does not establish whether mono sounds better or worse.
The line 'MIDI: Opened device:none' describes the configured DOSBox
MIDI output; it is not direct evidence that OPL/FM is unavailable.
The current DOSBox SB16 configuration has oplmode=auto.

A single focused browser FM detection comparison is available:
r05-sb16-8-adlib.jsdos preserves the partially audible W_SB16_8.DLL
effects and NoMixer, replaces A32SBFM.DLL by the original
owner-provided A32ALGFM.DLL, and selects MidiBase: 388h, the fixed
AdLib/OPL port. MidiIRQ/MidiDMA=-1 retain the Miles driver defaults.
The original MIDI_SB.HQR bank remains with MidiType: Fm.

Successful driver initialization does NOT automatically restore
ordinary scene music: the minimal data-only ISO contains no CDDA.
If AdLib also fails its hardware probe, stop guessing MIDI settings.
Compare the same private patched game bundle in native DOSBox and
js-dos 6.22. A native-vs-browser footstep comparison can distinguish
host/browser emulation from the legacy sound drivers/configuration.
No GOG executable, resource archive, DLL, or generated bundle should
be committed or published.
