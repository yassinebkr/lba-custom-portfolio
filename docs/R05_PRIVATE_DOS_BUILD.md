# R05 — Rebuild the private DOS bundle on Debian

**Status:** Owner confirmed successful play of the private GOG-derived game on GitHub Pages (2026-11-13). Synthetic packaging/browser CI passed. Sound, named save loading and death behavior are still open runtime gates.

## Requirements

- Debian with Python 3.10+, Node.js and xorriso
- A clean owner-provided installation, separate from the damaged Windows NVMe
- A RELENT.EXE version accepted by the guarded four-site patcher

~~~bash
sudo apt install python3 nodejs xorriso
~~~

The source directory needs `RELENT.EXE`, `RESS.HQR`, `SPRITES.HQR`, `SCENE.HQR`, `LBA_BRK.HQR`, `LBA_BLL.HQR`, `LBA_GRI.HQR` and `SAMPLES.HQR`. Keep these assets outside Git.

## Build and verify

~~~bash
python3 scripts/runtime/build-private-jsdos.py \
  --base "/path/to/clean/lba1-dos" \
  --mods "./output" \
  --out "./web_deploy/lba1_portfolio.jsdos"
~~~

Or place the original files in the ignored `base_game/` directory and use:

~~~bash
bash scripts/build-web-bundle.sh
~~~

The builder patches a temporary executable after verifying the original byte signatures. It overlays selected private HQR files from `output/`, uses xorriso to produce `LBA.ISO` with ISO9660 label `ADELINE`, verifies the CD directory, and packs the canonical js-dos 6.22 ZIP with an explicit `.jsdos/` directory entry first. The owner-supplied game directory remains unchanged. `VOX.HQR` is excluded to reduce emulator memory demands.

Open the [GitHub Pages local-bundle importer](https://yassinebkr.github.io/lba-custom-portfolio/web_deploy/), select the private ZIP, and verify the real DOS menu, graphics, keyboard controls and scene entry. The archive stays in the browser and is never uploaded to GitHub Pages.

The [GPL community engine source](https://github.com/LBALab/lba1-classic-community) supports OpenWatcom 2 DOS compilation to `LBAD.EXE` or `LBADC.EXE`. Those executables need a separate launch compatibility assessment; the current importer and builder target the historically patched `RELENT.EXE`. Original LBA1 visual resources remain proprietary.

## R05.1 optional audio and scene-save experiments

The original silent bundle remains the baseline. Never guess a DOS sound driver name: `WaveDriver` is a filename that the DOS engine attempts to load. The first step is a read-only audit of the installed GOG DOS directory:

~~~bash
BASE=/mnt/fast-ssd/Games/Heroic/tlba-classic/Speedrun/Windows
python3 scripts/runtime/audit-dos-install.py --base "$BASE"
~~~

If a valid wave DLL is available and `LBA.CFG` references it, `--audio source-wave` can build a private experiment. Separately, `--audio sb16` uses the real owner-provided DOS driver `W_SB16.DLL` when it exists, even if the GOG configuration has audio disabled; this mode enforces a conservative size check and known SB16 220h/IRQ7/DMA1 settings. Both are experimental. Keep `--audio off` as the known silent baseline. No driver is downloaded or fabricated; music and speech remain disabled. Passing the build does not prove audible sound.

Historic source code also provides seven pre-positioned DOS scene saves:

~~~bash
node scripts/hqr-tools/create-savegame.js museum --dos --no-deploy
python3 scripts/runtime/build-private-jsdos.py \
  --base "$BASE" \
  --mods ./output/r05-empty \
  --saves-dir ./output/saves/dos \
  --audio off \
  --out ./web_deploy/lba1_museum_probe.jsdos
~~~

The output has one or more `Snnn.LBA` slots at ZIP root. Test them through the **Continue Saved Game** menu. The bundle does not automatically jump to that scene; the direct-boot patch was historically planned, not merged.

Full test plan and historical provenance: [R05 runtime recovery](R05_RUNTIME_RECOVERY.md).

## Tests and limitations

~~~bash
python3 -m unittest discover -s scripts/runtime -p 'test_private_jsdos.py' -v
~~~

[CI proof — synthetic ISO and ZIP build](https://github.com/yassinebkr/lba-custom-portfolio/actions/runs/43359708088) and [browser integration using the real js-dos 6.22 ZIP extractor](https://github.com/yassinebkr/lba-custom-portfolio/actions/runs/43360752067). The browser test imports a bundle generated by the Debian builder; it verifies the ISO9660 volume label, patched executable offsets, resources and DOS command arguments while intercepting execution of the synthetic executable.

CI uses synthetic HQR placeholders and a fabricated patch-site executable. This proves packaging structure and failure handling. **It does not prove in-game audio, scene-save compatibility or reliable game-over handling.** Real gameplay startup has been separately owner-confirmed. The ISO and bundled ZIP may include build timestamps, so byte-identical SHA-256 values are not guaranteed between builds.

Never use the damaged Windows NVMe for this procedure. Do not commit any generated executable, HQR, ISO or .jsdos file. If the patcher reports incompatible bytes, identify the game release instead of bypassing its safety checks.


### Single-command private test matrix (R05.1)

From the experimental fix/r05-1-runtime-probes branch, run:

~~~bash
cd ~/Documents/lba-custom-portfolio
git fetch origin
git switch fix/r05-1-runtime-probes
BASE=/mnt/fast-ssd/Games/Heroic/tlba-classic/Speedrun/Windows

python3 scripts/runtime/audit-dos-install.py --base "$BASE"
python3 scripts/runtime/inspect_gameover_resources.py --base "$BASE"
python3 scripts/runtime/run-r05-probes.py --base "$BASE"
cat output/r05-probes/report.json
~~~

This creates a known silent control named output/r05-probes/r05-silent.jsdos
and, conditionally, r05-source-wave.jsdos and/or r05-sb16.jsdos. All are
ignored private assets, and no game input files are modified. The report
shows which audio profiles were skipped, the seven DOS save slots and
the presence/absence of the game-over model and sound index entries.

Open the local launcher on this branch at http://localhost:8765/?r05debug=1
after running python3 -m http.server 8765 from web_deploy/. Import one bundle
at a time. In the game's Continue Saved Game menu, try Museum S003, House
S002 and Proxima S005. For audio, compare an identical action and scene
between r05-silent.jsdos and r05-sb16.jsdos. For death, test loss of a
clover life and a terminal GameOver separately.

For diagnostic snapshots, run this in the browser console before and after
the black screen:

~~~js
copy(JSON.stringify(window.lbaR05DiagnosticReport(), null, 2));
~~~

The snapshot includes web-side errors and canvas visibility/focus, but not
the DOS program counter, video pixels or the emulated CPU state. Screen
captures and the behavior of ESC/menu after fifteen seconds are necessary.
Do not confuse a successful synthetic CI run with in-game behavior.

Only if these manual gates pass should sound be enabled by default or
direct-boot patching begin. Preserve all original LBA1 assets outside Git.
